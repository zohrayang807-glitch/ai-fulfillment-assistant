# 数据迁移方案：从 Olist（巴西）到抖音电商

> 目的：回答面试必问题"你的数据是巴西的，跟抖音有什么关系？"——结构化论证"什么通用、什么要替换、抖音有什么优势"。

## 一、诚实的前提：为什么用巴西数据

- Olist 是全世界结构最完整的**公开**电商数据集（订单/时效/评价/卖家全链路），而抖音交易数据是绝密的、个人拿不到；
- 用它的目的：**验证分析框架和方法论**，不是声称"巴西代表中国"；
- 局限诚实承认：数据年龄（2016-2018）、地域（巴西），但**方法论与市场无关**。

## 二、通用层：框架直接迁移（不依赖市场）

| 框架/方法 | 为什么通用 |
|---|---|
| 分位数分析（P50/P90） | 任何时效预测都需要，与市场无关 |
| 代理信号思路（差评含退货词→退货风险） | 没有直接退货数据的平台都用这思路 |
| 多因子决策框架（时间/风险/成本） | 人类购买决策的通用维度 |
| 层级回退（冷启动兜底） | 任何数据稀疏场景都需要 |
| 数据纪律（口径统一/可复现/标注样本） | 普世的数据素养 |

## 三、本地化层：必须替换（诚实列出差距）

| 维度 | Olist | 抖音电商 |
|---|---|---|
| 数据源 | 公开订单数据 | 内部交易/物流数据（入职后可及） |
| 退货词典 | 葡语关键词（devol/troca...） | 中文（"退货""退款""不给退"） |
| 类目体系 | Olist 类目 | 抖音电商三级类目 |
| 地理粒度 | 州级 | 城市/区县级 + 物流节点 |
| 时效模式 | 巴西邮政为主 | 四通一达 + 京东物流 + 抖音物流 |

## 四、增量层：抖音独有的优势（比巴西更强）

- **实时物流 GPS**：不只是历史分布，有实时承诺能力；
- **直播间场景**：冲动消费 → 时效敏感度更高；
- **短视频种草→下单链路**：决策场景前置，助手能介入更早；
- **支付/退款数据**：真实退货率，不只是代理信号；
- **客服日志**：真实用户问题，可做需求验证。

## 五、落地三步走（如果有抖音数据）

1. **第一步（1-2 周）需求验证**：用客服日志/搜索 query 验证"时间/风险/成本"是否真是用户痛点；
2. **第二步（2-4 周）架构落地**：接实时物流 API，把"历史画像 + 实时承诺"两阶段架构落地；
3. **第三步 灰度迭代**：跑评测集 + 灰度，用指标迭代。

---

**面试一句话总结：**

> "我用了巴西公开数据验证框架，因为它是唯一能拿到的完整数据集。框架的通用层（分位数、代理信号、多因子、层级回退）与市场无关；本地化层（词典、类目、地理、时效模式）我清楚要替换什么；抖音的实时 GPS、直播间、支付数据反而让这套框架能做得更深。"
