# 产品说明书 — 履约 AI 购物助手 V2.0

> 版本：v2.0（已上线）｜本文档描述产品当前实际能力与使用方式

---

## 一、产品是什么

**懂履约的 AI 购物助手**：用户网购下单前，基于历史履约数据，帮助判断"哪家靠谱、多久能到、多少钱值得买"。

与平台"一刀切"承诺不同，它给出个性化履约预期——精确到"这家店在哪个州发货、发货快不快、送到你那多久、平台承诺多久、实际准时率多高"。

---

## 二、能做什么（四大能力）

### 1. 时效判断
- 拆段回答：发货快不快 + 运输多久 + 总时长
- 承诺对比：平台承诺 vs 实际偏差、准时率
- 可预测性：九成订单在多少天内

### 2. 卖家风险
- 差评率、与类目平均对比
- 跨品类表现（哪些类稳、哪些差）
- 差评原因（主要被骂什么）

### 3. 成本对比
- 到手价（标价+运费）、运费参考
- 性价比评分（价格+时效+风险加权）
- 多卖家对比

### 4. 卖家推荐
- 按品类筛靠谱卖家（差评低于类目平均）
- 附带送达时效

### 其他
- 对比 / 聚合排名（哪些品类运费最贵等）
- 对话类：介绍能力、解释方法、拒绝不支持、闲聊

## 三、怎么用

### 助手页面
```
浏览器打开助手网址 → 填昵称 → 输入问题
```

示例问法（大白话即可）：
- "b1a812 多久能发货"
- "买书架送到 SP 要多久"
- "282f23 和 a3dd39 哪个靠谱"
- "b1a812 和 5058e8 哪个便宜，书架送到 RN"
- "推荐个卖咖啡的，送到 RN"
- "哪些品类运费最贵"

### 运营后台
```
助手网址 + /admin
```
包含：指标看板 / 模型管理 / 测评管理 / Agent 管理。

---

## 四、数据说明（诚实标注）

- **数据来源**：巴西 Olist 电商公开数据（2016-2018）
- **数据性质**：用于验证方法论，**数值不反映当前情况**
- **非实时**：基于历史数据，仅供参考
- **无长期记忆**：会话内 5 轮上下文，关闭后不记得

---

## 五、运营后台功能

| 模块 | 功能 |
|---|---|
| **指标看板** | 对话数、模型调用、token、成本、Eval 通过率、坏例数 + 趋势 |
| **模型管理** | 主模型/裁判模型切换、token 统计、成本明细 |
| **测评管理** | Eval 中心（用例编辑/运行/历史）+ 坏例闭环（标记→Eval+BUG 单） |
| **Agent 管理** | 干预开关（功能/州/品类）+ 提示词调优（版本回滚 + AB） |

### 坏例闭环（核心运营流程）
```
发现坏例 → 后台标记（填原因）→ 进 Eval 用例 + BUG 反馈单 → 跑 Eval 验证
```

---

## 六、已知边界与局限

1. **数据是历史巴西数据**，不能代表现在的抖音场景，用于验证方法论
2. **卖家级差评原因样本可能稀疏**（差评文本少），查不到时诚实说明
3. **对话评审默认关闭**（省 token），需要时在干预开关开启
4. **后台新增坏例**：会进 Supabase，但本地 Eval 文件可能需要同步（当前 Eval 读 Supabase）
5. **无长期记忆**：会话内 5 轮，关掉重开不记得（设计选择）

## 七、快速开始（开发者）

```bash
# 依赖
pip install -r requirements.txt

# 本地运行
streamlit run app_v2.py          # 助手
streamlit run pages/admin.py     # 后台

# Eval
python eval/eval.py              # 32 条，20 秒
```

### 部署（Streamlit Cloud）
1. 代码推 GitHub
2. Streamlit Cloud 连接仓库，主文件 `app_v2.py`
3. 配置 Secrets（DEEPSEEK_API_KEY / SUPABASE_URL / SUPABASE_KEY）
4. 部署后即可访问

### 数据库（Supabase）
- 5 张表：conversations / evaluations / cases / bug_feedback / prompt_versions
- 关闭 RLS（共享访问）
- 建表 SQL 见 `supabase_schema.sql`
