## ④ 注意事项（踩过的坑，务必记住）

### 数据层
1. **类目命名**：Olist 有两套类目（葡语 moveis_escritorio / 英语 office_furniture），全项目统一用英语
2. **差评率分母**：用"差评数÷评论数"，不是"÷订单数"（沉默者偏差）
3. **多对多归属**：评价是订单级，一单多卖家时"取第一个商品"会漏/错配，query_seller_risk 已改卖家级聚合
4. **卖家缩写**：短前缀会匹配多个卖家，必须做唯一性检查，匹配多个就诚实说"不唯一"
5. **结论方向**：不仅数字要对，"谁高谁低、谁快谁慢"的方向也要对
6. **数字三方对齐**：故事 md / provenance 脚本 / 知识库，三处数字必须一致
7. **cat_avg_return_kw ≠ 差评基线**：那是退货词提及率均值（0~9%），差评基线用 category_baseline.neg_rate
8. **卖家 ID 不是卖家州**：query_timing 第一个参数是 seller_state，传 seller_id 永远匹配不到；先 query_seller_state 反查

### 评分与口径
9. **min-max 归一化抹平绝对差距**：价格差 3.7 倍和时效差 2 天被压成同等 0/1 → 用相对比例 score=min/value 保留差距
10. **neg_rate 双口径**：seller_risk 与 seller_cost 同卖家同品类值可能不同，评分统一从 seller_risk 取并标注来源，回答层别混用
11. **卖家级差评原因样本稀疏**：差评文本少的卖家查不到原因，诚实标注"无法拆解"或回退品类，不编造

### 多意图
12. **缺参数软指令会被 LLM 忽略**：多意图部分意图缺参数时，必须用强指令（"违反即失败"）强制回答说明缺什么、缺失维度禁下结论
13. **多意图 time 只取第一个卖家**：seller_ids 有多个时 time 用第一个的发货州，是已知简化

### 数据边界
14. **数据是 2016-2018 巴西数据**：不能声称代表现在，作品里诚实标注"用于验证方法论"
15. **无实时数据**：回答要标"基于历史数据，仅供参考"
16. **无长期记忆**：只有会话内5轮上下文（设计选择，不是bug）

### 安全
17. **API key 不进 git**：.env 已在 .gitignore，提交前确认没把 key 提交进去
18. **Notion API 凭证**：用完即清理，别随便发凭证

### Agent 设计原则（用户强调的）
19. **不要固定话术**：capability/methodology 等让 LLM 动态生成，发挥大模型特点
20. **数字不让 LLM 算**：数字一律 query.py 查知识库，LLM 只组织语言（防幻觉的架构保证）
21. **信息分层**：用户侧只给模糊结论（约/大概/左右），底层数据（n/P50/P90）放 trace 给面试官看
