# PRD — 懂履约的 AI 购物助手

> 版本：v2.0（已上线）｜作者：杨智东｜关联文档：AI 架构、产品说明书、能力地图、任务清单

## 一、产品定位

**懂履约的 AI 购物助手**：帮用户在网购下单前做购买决策，基于历史履约数据，告诉用户"哪家靠谱、多久能到、多少钱值得买"，并解释为什么。核心价值是**比平台"一刀切"承诺更真实的履约预期**——能精确到"这家店在哪个州发货、发货快不快、送到你那多久、平台承诺多久、实际准时率多高"。

数据来源为巴西 Olist 电商公开数据验证框架，产品落地场景为抖音电商。

## 三、核心能力（V2.0 已实现）

### 三元组意图架构

意图识别从"单标签"升级为**三元组**（操作 × 维度 × 指标）：

- **操作**：query 查询 / compare 对比 / aggregate 聚合 / recommend 推荐
- **维度**：seller 商家 / category 品类 / route 路线
- **指标**：ship_time 发货 / transit_time 运输 / total_time 总时长 / freight 运费 / price 价格 / neg_rate 差评 / ontime_rate 准时 / promise_gap 承诺偏差

（详见 notes/履约AI助手V2.0设计文档.md 和 notes/capability 能力地图）

### 功能清单（V2.0 实际实现）

| 能力 | 说明 |
|---|---|
| 时效判断 | 发货段 + 运输段拆解、承诺 vs 实际偏差、准时率、可预测性 |
| 卖家风险 | 差评率、跨品类表现、差评原因 |
| 成本对比 | 到手价、性价比评分（价格+时效+风险加权） |
| 卖家推荐 | 按品类筛靠谱卖家（差评低于类目平均） |
| 多对象对比 | 多卖家循环对比（发货/时效/价格/风险） |
| 聚合排名 | 品类运费、路线运费排行榜 |
| 对话类 | 能力介绍 / 方法论 / 不支持 / 闲聊 |

## 四、关键交互示例（真实可用）

**时效（拆段回答）**
> 用户：a3dd39 发到 MG 多久？
> 助手：总共大概 10 天——发货段一两天就交快递，运输段路上大概 8-9 天。平台承诺约 26 天，实际平均 10 天出头，绝大多数能按时甚至提前到。

**风险（跨品类）**
> 用户：282f23 和 a3dd39 哪个靠谱？
> 助手：a3dd39 更靠谱一点——差评率约 3%，282f23 约 4%。a3dd39 专注一个类目更专精。

**成本（性价比）**
> 用户：b1a812 和 5058e8 哪个便宜，书架送到 RN？
> 助手：5058e8 更值——到手约 197 雷，b1a812 约 348 雷，差 150 雷。

**推荐**
> 用户：推荐个卖咖啡的，送到 RN
> 助手：挑了 3 家差评率低、评论量够的卖家，分别从 SP/RN/SP 发货，送到 RN 时效 12-14 天。

**坏例兜底**
> 用户：各品类发货速度排名
> 助手：发货是商家行为，不同品类没有统一规则。可以告诉我某家店，或推荐发货快的卖家。

## 五、指标设计（实际落地）

### Eval 评测（离线自动）

- **评测集**：32 条用例（防复发 8 + 能力矩阵 16 + 边界 7 + 坏例 1）
- **三重判分**：意图匹配 + 禁止词（防幻觉）+ 必须词（引导正确）
- **当前通过率**：100%
- **并发提速**：32 条 20 秒跑完（5.4×）
- **数据源**：Supabase（坏例直接进 Eval）

### 双层评审

- **框架评审**（代码规则）：数据一致性、拆段、防编造
- **模型评审**（裁判模型 v4-pro）：准确性/完整性/语气/防幻觉打分

### 在线指标（未来上线后）

|---|---|
| 业务 | GMV、转化率、客单价 |
| 履约效果 | 退货率、客诉量 |
| 用户行为 | 推荐采纳率、复购率 |

## 六、风险与失败兜底（实际实现）

| 风险/失败场景 | 兜底方案（已实现） |
|---|---|
| 数据缺失 | 层级回退到粗粒度数据 + 标注不确定性 |
| LLM 幻觉（编造） | 数字由数据层计算，LLM 只组织语言；缺失维度禁编造 |
| 小样本 | 标注样本量，结论仅参考 |
| 缺参数 | 全部缺合并反问；部分缺单独提示 |
| 对话评审失败 | 评审开关控制，默认关闭对话评审，Eval 才评审 |
| 坏例格式异常 | normalize_case 规范化，统一字段 |

## 七、运营后台（V2.0 已实现）

| 模块 | 功能 |
|---|---|
| **指标看板** | Agent+模型双看板：对话数、调用数、token、成本、Eval 通过率、坏例数 |

| **双层评审** | 框架评审 + 裁判模型打分 |

## 八、多人协作与部署

- **用户昵称**：对话/坏例/Eval/版本记录都带操作者
- **云端部署**：Streamlit Cloud + Supabase 数据库（数据持久，多人共享）
- **坏例闭环**：标记坏例 → 规范化进 Supabase → Eval 直接跑到 → 报表可视化
