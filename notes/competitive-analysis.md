# 竞品综合分析报告：四大平台 AI 购物助手

> 分析对象：豆包（抖音）、问点点（小红书）、京言（京东）、千问（淘宝）
> 方法：行为测试 + 系统提示词逆向工程（5 组手法）
> 目的：验证"履约数据驱动的购物助手"的差异化空间
> 日期：2026-08-11

## 二、核心发现

### 发现 1：卖家履约数据 = 四家全空白（最关键）

- **四家都查不到**：卖家履约数据、退货率、资质、履约可靠性；
- **但三家能查实时价格/物流/时效**（京言/千问/问点点）——说明"平台数据权限"和"卖家履约数据"是两回事；
- **京言甚至承认"是权限问题"**——它作为京东生态内助手，也只开放了商品和基础搜索，没开放商家后台履约记录。

**结论：卖家级履约数据，即使数据能力最强的京言、千问，也没对消费者开放。这是四家的结构性空白——正是"平台内部 AI 产品"的机会。**

### 发现 2：三种"立场"的差异（消费者/模糊/平台）

- **豆包**：消费者侧（中立不带货）→ 诚实，但有商业张力（对抗平台 GMV）；
- **京言/千问**：平台侧（导购转化）→ "诚实"让位于"销售"（京言不会说"别在京东买"）；
- **问点点**：立场模糊 → 不承诺也不推销。

**结论：立场是核心设计决策。你的产品需要在"诚实"和"平台 GMV"之间找平衡（对应商业闭环章节）。**

### 发现 3：四种安全策略（提示词工程的战场）

- **豆包**：黑名单式（规则透明，但可被"PM 角色扮演"套取）；
- **问点点**：模糊拒绝式（不承认规则、识别套路，安全最强）；
- **京言**：混合式（能力透明、设定保密，但拒绝话术弱）；
- **千问**：半透明式 + **用户验证**（"你理解得很准"——主动确认用户理解价值）。

**结论：你的助手要防 prompt 注入（参考问点点），也要有"数据来源透明"的话术（参考千问）。**

### 发现 4：实时能力分层

```
无实时（豆包）→ 价格/行情（问点点）→ 平台物流/时效（京言/千问）
```
但**卖家履约数据是最后一块没被打开的**——行业趋势是"消费者端助手越来越接实时数据"，履约数据是真空。

---

## 三、机会点提炼（你的差异化）

1. **卖家级履约数据 = 四家结构性空白**（时效可靠性、退货率、履约风险）——你的核心补位；
2. **"诚实 + 数据"的平衡**：豆包有诚实无数据，京言有数据无诚实（平台导向）——你的产品：**有数据 + 敢诚实**（用商业闭环解决张力）；
3. **可复现的数据纪律**：四家的"时效判断"都是给建议不给数据；你能给 **P50/P90 + 样本标注**——它们都没有的透明度。

## 四、对你的产品的启示

| 维度 | 竞品现状 | 你的方案 |
|---|---|---|
| **定位** | 京言/千问有数据权限、豆包有诚实立场 | **平台内部 AI（有数据）+ 诚实立场（学豆包）**，用商业闭环支撑 |
| **能力** | 千问/京言接了实时价格/物流 | 接实时数据 + **补上它们没有的卖家履约数据** |
| **安全** | 问点点防注入最强 | 防 prompt 注入（学问点点）+ 数据来源透明（学千问） |
| **话术** | 豆包太客服风、问点点太朋友风 | 找"专业感 + 亲近感"的平衡 |
| **时效** | 四家都不给数据结论 | **给 P50/P90 + 样本标注（可复现）** |

## 五、一句话总结（面试开场白）

> "我调研了四大平台的购物助手：豆包、问点点、京言、千问。发现行业共性——**产品级对比、实时价格、物流追踪都有了，但卖家级履约数据（时效可靠性、退货率、履约风险）四家全是空白**，即使数据能力最强的京言、千问也没打开。因为消费者端助手拿不到这层平台数据。我的产品定位是**平台内部 AI**，正好补这个结构性空白——用履约数据驱动决策，而且敢把数据来源讲清楚、可复现。"
