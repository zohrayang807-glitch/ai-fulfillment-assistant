# 懂履约的 AI 购物助手 — 作品集

用 Olist 巴西电商公开数据，从"数据分析"到"AI 产品"完整落地一个**懂履约的购物助手**：基于历史履约数据，为用户下单前提供比平台承诺更真实的判断（哪个卖家靠谱、多久能到、多少钱值得买）。

## 背景与核心洞察

平台承诺时效普遍保守失真（平均提前 11.3 天、迟到率 7.6%），用户无法据此安排收货。AI 购物助手的核心价值：**基于历史履约数据，给出比平台承诺更真实、可拆解到"发货/运输"两段的预期**。

- 目标岗位：抖音电商 AI 购物助手方向产品经理
- 数据：巴西 Olist 电商数据集（2016-2018，约 9.6 万笔已完成配送订单）
- 落地场景：抖音电商（方法可迁移，数据用于验证方法论，数值不反映当前）

## 产品能力

### V1 → V2 的架构演进

- **V1（单标签意图）**：time/risk/cost 等标签，每加一个能力加一个意图
- **V2（三元组架构）**：意图识别升级为 `操作 × 维度 × 指标` 三元组，加能力 = 映射表加一行

### V2 四个操作

| 操作 | 说明 |
|---|---|
| **query** | 单对象查询（某家店发货多久、送到 SP 要多久） |
| **compare** | 多对象对比（两家谁发货快、哪家便宜，多对象循环是通用逻辑） |
| **aggregate** | 维度级排名（哪些品类运费最贵、哪些路线运费最贵） |
| **recommend** | 按品类筛靠谱卖家 + 拼送达时效 |

### 核心指标（8 个）

发货时长 · 运输时长 · 总时长 · 运费 · 价格 · 差评率 · 准时率 · 承诺偏差

### 防幻觉架构（项目铁律）

- 数字全部由数据层（query.py / query_v2.py）精确查询，LLM 只负责组织语言
- 缺失维度禁编造（没查价格不说"综合推荐"，没查时效不编天数）
- 数据模糊化（约/大概/左右/九成），底层精确值放推理链路（trace）
- 只答用户问的指标，不脑补没问的维度

## 技术选型与理由

| 问题 | 选择 | 为什么 |
|---|---|---|
| 数据是精确数值，不是文本 | **结构化知识库 + 确定性查询**，不用 RAG | RAG 检索文本会有数字漂移，精确数值必须确定性查询 |
| 意图 → 工具调用 | **prompt + 代码路由**（LLM 报三元组，映射表查函数），不用原生 function calling | 函数路由由代码决定、可审计，避免 LLM 调错工具 |
| 能力组合 | **三元组正交架构**（操作×维度×指标） | 加一个指标 = 三个操作自动点亮，而非逐个加意图 |

## 快速开始

```bash
# 1. 下载数据集到 olist/ 目录
# 2. 安装依赖
pip install pandas openai streamlit python-dotenv

# 3. 命令行测试（V2）
python agent_v2.py

# 4. 网页（V2）
streamlit run app_v2.py

# 5. Eval 回归（每次改代码后跑）
python eval/eval.py        # 当前 31/31 通过
```

## Eval 评测工程（自动防线）

- **31 条用例**，覆盖：历史踩坑（防复发）、能力矩阵（每个操作×维度×指标）、通用边界（防幻觉/缺参引导/排序方向）
- **三重判分**：意图匹配 + 禁止词（防幻觉）+ 必须词（引导正确）
- **每次改代码后跑 Eval**，漏一个自动拦截，防止"修 A 引 B"的回归

## 关键数据发现

| 指标 | 数值 | 说明 |
|---|---|---|
| 承诺提前送达率 | **90.4%** | 平均比承诺早到 11.3 天，承诺严重保守 |
| 实际配送 P50 / P90 | **10.2 / 23.1 天** | 中位正常，尾部体验差 |
| 卖家发货时长 | **0 ~ 26 天** | 卖家间差异极大（食品类当天，办公家具 10 天） |
| 运输段中位 | **7 天** | 品类几乎无影响，主要看路线距离 |
| 运费占总价比 | **中位 18.8%** | 巴西运费占比高，到手价决策关键 |
